# Ponte Dom — frontend language consistency (November 2026)

## Scope
Visitor-facing Polish (pl), English (en), and Italian (it) listing cards and links. No visual redesign or production deployment in this branch.

## Findings
- The frontend requested `/api/listings` without a `lang` parameter, so the backend defaulted to Polish.
- Listing detail links did not preserve the selected language.
- The listing normalization layer discarded `localizedTitle` and `localizedDescription` objects.
- The property detail title reset to Polish.
- Dynamic language switches could keep the previously loaded listing data.

## Changes
- Request `/api/listings?lang=<selected>` and reload when the language changes.
- Preserve localized title and description objects when available.
- Add `?lang=<selected>` to internal backend listing links, preserving existing query parameters.
- Localize the document title and remove a redundant detail re-render.

## Acceptance tests (manual browser verification required)
1. Open `/`, `/en`, `/it`; inspect navigation and cards in each language.
2. Switch PL → EN → IT without reloading; check listing titles and descriptions.
3. Open a listing card and verify `?lang=` on the backend detail URL.
4. Test list/cards/large views, map pins, filters, pagination, inquiry forms, and analytics.
5. Check the browser console and Network tab for failed requests.
6. Check listings with missing translations: the backend reports translationStatus, but fallback content may still appear until data is repaired.

## Follow-up
Audit existing MongoDB listings for missing or mislabeled translations. Coordinate with the backend PR before merging; the API contract is shared.
